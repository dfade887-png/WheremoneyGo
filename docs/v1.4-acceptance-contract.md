# v1.4 Acceptance Contract

No deliverable APK is allowed until all release blockers pass automated and emulator Golden Path validation.

The Real Profile path must allow the user to configure payday policy, create multiple accounts without forced cash, select salary/savings/emergency accounts, configure multiple obligations, finalize once, record income/expense/transfer, correct transactions, restart, and backup/restore without profile leakage or Flutter exceptions.

All money comes from SQLite and FinancialSnapshot. Opening balances and historical progress are not income or expense. Transfers do not change combined money. No Demo seed is allowed in a Real Profile.

Temporary routes must close before root profile or setup state changes. Database failure must not navigate. Every async UI action requires mounted checks and double-submit protection.

Validation evidence must include analyze, all tests, emulator logcat, restart, backup/restore, and small-screen keyboard checks. A validation tag is forbidden before physical-device acceptance.
